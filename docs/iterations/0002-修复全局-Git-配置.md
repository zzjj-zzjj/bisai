## 验证方式

关键验证是**只依赖全局配置**能否完成一次全新克隆——这能同时证明无代理可用、
身份已继承、公开仓库可匿名读取：

```powershell
# 克隆到临时目录，不使用任何 -c 覆盖
git clone https://github.com/zzjj-zzjj/bisai.git $env:TEMP\bisai-verify
git -C $env:TEMP\bisai-verify config user.name
git -C $env:TEMP\bisai-verify config user.email
git -C $env:TEMP\bisai-verify log --oneline
Remove-Item $env:TEMP\bisai-verify -Recurse -Force
```

同时确认仓库级配置已精简为只含默认项：

```powershell
git -C D:\bisai config --local --list   # 不应出现 user.* / *.proxy
git config --global --list              # 应只有 user.name / user.email
```

## 结果与结论

全部通过：

- `D:\bisai` 的仓库级配置只剩 `core.*`、`remote.*`、`branch.*` 默认项，无冗余覆盖。
- 全局 `https.proxy` 已不存在，`git config --get https.proxy` 返回空。

补充确认：仓库已是**公开**状态（`private: false`，匿名读取 refs 成功），
因此以后换机器部署也不需要配置凭据。

一个值得记住的教训：`git ls-remote` 在代理不可达时会**退出码 0 且零输出**，
而不是报错。若只检查退出码，会误判为"空仓库"。判断仓库是否为空，
应改用 `git ls-remote` 的输出内容，或直接看 GitHub API 的 `size` / `pushed_at` 字段。
